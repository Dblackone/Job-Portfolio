# Quick Tip Bank

200 short-form educational posts across ten formats. Each is a complete Wednesday slot, a
WhatsApp status, or a graphic card.

**Format for every tip:** dark or cream card per `../BRAND.md` · eyebrow = format name ·
Bebas headline · 1–2 lines Inter body · footer lockup. No emoji.

**Accuracy rule:** every shortcut below is listed as **commonly default**. Shortcuts can be
customised and vary by version and discipline. The honest, always-correct instruction is:
**type `KS` to see what your own install has mapped.** Say that in the content, not just here.

**Usage rule:** never post two tips from the same format in the same week.

## 1. Revit Shortcut of the Day (20)

*Verify each against `KS` before posting.*

| # | Shortcut | Headline | Body |
|---|---|---|---|
| 1 | `KS` | THE ONLY SHORTCUT LIST THAT IS TRUE FOR YOU | Opens the Keyboard Shortcuts dialog. Every list online, including mine, is a guess about your install. This is not. |
| 2 | `WA` | WALL | The one you will type most. Set the location line on the Options Bar before you draw. |
| 3 | `DR` / `WN` | DOOR / WINDOW | Both hosted. Press spacebar while placing to flip the hand. |
| 4 | `LL` / `GR` | LEVEL / GRID | Levels in elevation. Grids in plan. Never the other way round. |
| 5 | `VG` or `VV` | VISIBILITY / GRAPHICS | The second place to look when something is missing. View range is the first. |
| 6 | `HR` | RESET TEMPORARY HIDE | If the view has a cyan border, something is hidden. This resets it. |
| 7 | `HH` / `HI` | HIDE / ISOLATE ELEMENT | Temporary. Both leave the cyan border that tells the next person what happened. |
| 8 | `EH` | HIDE ELEMENT IN VIEW | Permanent, unlike HH. Use deliberately, because nobody can see that you did it. |
| 9 | `MA` | MATCH TYPE PROPERTIES | Click the element you want, then the element to change. Faster than the type selector. |
| 10 | `CS` | CREATE SIMILAR | Select anything, press CS, and you are placing another one with its settings. |
| 11 | `AL` | ALIGN | Pick the reference first, then the thing to move. Then click the padlock to keep it. |
| 12 | `TR` | TRIM / EXTEND | Click the part of the element you want to **keep**. That is the bit people get backwards. |
| 13 | `SL` | SPLIT ELEMENT | Splits walls, lines and beams at a point. |
| 14 | `OF` | OFFSET | Set the distance on the Options Bar first, then pick. |
| 15 | `PN` / `UP` | PIN / UNPIN | Pin your grids, levels and links. It costs nothing and prevents a bad afternoon. |
| 16 | `TL` | THIN LINES | Toggles line weights off on screen. Essential when checking alignment. |
| 17 | `ZF` / `ZR` | ZOOM TO FIT / REGION | Or double-click the middle mouse button for zoom to fit. |
| 18 | `WT` / `WC` | TILE / CASCADE WINDOWS | Tile a plan and a 3D view side by side. Best modelling habit there is. |
| 19 | `DI` | ALIGNED DIMENSION | Dimension to model references so it updates when the model does. |
| 20 | `RP` | REFERENCE PLANE | In families, reference planes come before geometry. Always. |

| # | Headline | Body |
|---|---|---|

| 2 | ATTACH WALLS TO ROOFS | Modify → Attach Top/Base. Better than editing the profile, because it updates. |
| 3 | PICK WALLS, DO NOT DRAW LINES | When sketching floors. One creates a relationship. The other creates a shape. |

| 5 | DUPLICATE BEFORE YOU EDIT A TYPE | Otherwise you just changed every element of that type in the project. |
| 6 | TAG ALL NOT TAGGED | Tags every untagged element of a category in the view in one operation. |
| 7 | LEGENDS GO ON MULTIPLE SHEETS | Every other view type cannot. That is why legends exist. |
| 8 | UNTICK "ITEMISE EVERY INSTANCE" | Turns a 240-row door list into a 6-row summary with quantities. |
| 9 | SECTION BOX IN A 3D VIEW | The fastest way to show someone a coordination problem. |
| 10 | DUPLICATE AS DEPENDENT | For a large floor split across sheets. The parent controls all the children. |
| 11 | NAME VIEWS ON CREATION | Two seconds now. Hours later. |
| 12 | SET THE ACTIVE WORKSET BEFORE MODELLING | Elements land on whatever is active. This catches everyone once. |
| 13 | RELOAD LINKS BEFORE COORDINATION | Reviewing last month's model wastes everyone's hour, not just yours. |
| 14 | CURRENT VIEW ONLY, FOR CAD | Tick it when linking a survey you are tracing from. |
| 15 | SAVE YOUR PRINT SELECTION SETS | Name them by issue package. Fifteen minutes back, every issue. |
| 16 | PRINT AT 100%, NEVER FIT TO PAGE | Fit to page silently changes your scale. |
| 17 | RECREATE YOUR LOCAL MODEL WEEKLY | Local files accumulate problems that are hard to diagnose. |
| 18 | SET THE 3D EXTENT OF GRIDS | Or they appear in one view and not the next, and it looks like a bug. |
| 19 | REFLECTED CEILING PLAN, NOT FLOOR PLAN | Different view. Beginners routinely model ceilings in the wrong one. |
| 20 | CHECK THE PDF BEFORE YOU ISSUE | Every time. Missing views and wrong revisions show up there, not on screen. |

## 3. Did You Know? (20)

| # | Headline | Body |
|---|---|---|
| 1 | THE TERM IS FROM 1992 | "Building Information Model" was first documented in print by van Nederveen and Tolman. |
| 2 | THE IDEA IS FROM 1975 | Charles Eastman described a single integrated database for visual and quantitative analysis. |
| 3 | THEY DESCRIBED FEDERATION IN 1992 | Aspect models from different participants combining into one reference model. We still explain this in meetings. |
| 4 | "BIM LEVEL 2" IS NOT IN ISO 19650 | BSI's own transition material says so. It is historical UK terminology. |
| 5 | EIR MEANS EXCHANGE, NOT EMPLOYER'S | It changed with ISO 19650. Using the old term dates you instantly. |
| 6 | IFC IS AN ISO STANDARD | ISO 16739. Not just a file format. |
| 7 | COBIE IS A SUBSET OF IFC | Formally. The spreadsheet is just one way to carry it. |
| 8 | COBIE STARTED IN 2007 | Authored by William East of the US Army Corps of Engineers. |
| 9 | ISO 19650 HAS SIX PARTS | Part 6, health and safety information, arrived in 2025. |
| 10 | A CDE HAS FOUR STATES | Work in progress, shared, published, archived. With approvals between each. |
| 11 | SHARED MEANS COORDINATION ONLY | Not approved. That distinction ends most "was it issued?" arguments. |
| 12 | EDITING A SCHEDULE EDITS THE MODEL | It is bidirectional. It surprises everyone the first time. |
| 13 | DELETE THE WALL, LOSE THE DOOR | That is what hosted means. |
| 14 | COPYING A LEVEL CREATES NO PLAN VIEW | Drawing one does. This is why your new level has no plan. |
| 15 | THE VIEW LIST IS A VIEW | Schedule your views. It is the fastest view-standards audit there is. |
| 16 | REVIT MODELS DO NOT OPEN BACKWARDS | A newer version cannot be opened in an older one. Agree the version in the BEP. |
| 17 | A WORKSET STILL CALLED "WORKSET1" | Tells you everything about how that model is managed. |
| 18 | THE GEMINI PRINCIPLES DEFINED DIGITAL TWINS | Published December 2018 by the Centre for Digital Built Britain. Nine principles. |
| 19 | IFC 4.3 ADDED GEOREFERENCING | And the capacity to describe non-man-made objects. A major step for infrastructure. |
| 20 | LOD AND LEVEL OF DETAIL ARE NOT THE SAME | Level of detail is how much geometry. Level of development is how much you can rely on it. |

## 4. Common Mistake (20)

| # | Headline | Body |
|---|---|---|
| 1 | EXPLODING AN IMPORTED DWG | Injects thousands of foreign line styles permanently. The most common act of lasting damage there is. |
| 2 | IMPORTING INSTEAD OF LINKING | An import never updates and cannot be cleanly removed. |
| 3 | EDITING A TYPE WITHOUT DUPLICATING | You just changed every element of that type in the project. |
| 4 | ASSUMING IT WAS DELETED | Check view range, temporary hide, VG, filters, worksets, phase. Deleted is last. |
| 5 | CREATING LEVELS IN PLAN VIEW | Levels are made in elevation or section. Every beginner learns this once. |
| 6 | DRAGGING LEVELS INTO POSITION | You get 3,247 mm when you wanted 3,250 mm and do not notice for weeks. |
| 7 | IGNORING THE WALL LOCATION LINE | Walls that look right and measure wrong are almost always this. |
| 8 | SINGLE-LAYER GENERIC WALLS | No material takeoff, no meaningful detail, and an unhappy cost consultant. |
| 9 | BLAMING THE TAG | A blank tag means a blank parameter. Fix the model, not the tag. |
| 10 | TYPING DRAWING NUMBERS BY HAND | They become wrong, and cross-references stop working. |
| 11 | TYPING INFORMATION INTO A SCHEDULE | If the model should know it, it belongs in the model. |
| 12 | OPENING THE CENTRAL MODEL DIRECTLY | You are editing the master and blocking the whole team. |
| 13 | NOT RELINQUISHING BEFORE LEAVING | Borrowed elements block your colleagues all night. |
| 14 | SYNCHRONISING ONCE A DAY | Long gaps mean painful, conflict-heavy reconciliation. |
| 15 | NUDGING A LINK INTO PLACE | You just hid a coordinates problem. It will resurface at federation. |
| 16 | USING WORKSETS FOR GRAPHICS | Worksets manage ownership and loading. Graphics belong in view templates. |
| 17 | DESIGN OPTIONS AS A FILING CABINET | Accept or delete. They carry a permanent performance cost. |
| 18 | DELETING EXISTING ELEMENTS | Demolish them. Deleted elements cannot appear on a demolition plan. |
| 19 | ADJUSTING ONE VIEW INSTEAD OF THE TEMPLATE | The fix does not propagate, and the set drifts. |
| 20 | REGENERATING THE SHARED PARAMETER FILE | New GUIDs. Every existing reference silently stops matching. |

## 5. Best Practice (20)

| # | Headline | Body |
|---|---|---|
| 1 | LINK. NEVER IMPORT. NEVER EXPLODE. | Three rules. They prevent most permanent damage to project files. |
| 2 | ONE LINK, ONE WORKSET | Then people can unload what they are not using. Biggest performance win on a big project. |
| 3 | GRAPHICS LIVE IN TEMPLATES | If you are opening VG on one view, the fix probably belongs in the template. |
| 4 | ONE DISCIPLINE AUTHORS DATUMS | Everyone else uses Copy/Monitor. Two authors guarantees divergence. |
| 5 | FLEX YOUR FAMILY BEFORE LOADING | An unflexed family breaks in someone else's project, under deadline. |
| 6 | REFERENCE PLANES FIRST, GEOMETRY SECOND | In families. Always. Nothing flexes otherwise. |
| 7 | PUT SCHEDULES ON SHEETS IN WEEK ONE | An empty schedule on a sheet is a to-do list the whole team can see. |
| 8 | PIN YOUR DATUMS AND LINKS | It costs nothing and prevents a genuinely bad afternoon. |
| 9 | NAME TO A CONVENTION, FROM DAY ONE | Files, views, sheets, worksets, families, types, materials, parameters. In that order. |
| 10 | MODEL NEAR THE INTERNAL ORIGIN | Beyond about a kilometre, accuracy and display problems begin. |
| 11 | AGREE SHARED COORDINATES ONCE | At the start. Record them in the BEP. One sentence, one recurring argument prevented. |
| 12 | STAGGER YOUR SYNCHRONISATION | Everyone syncing at 17:00 makes a queue, and queues make people skip syncing. |
| 13 | AUDIT ON A SCHEDULE, NOT IN A PANIC | Weekly on a live project. Always before issuing to a CDE. |
| 14 | SAVE NAMED MILESTONE FILES | Backups roll over. Milestones do not. |
| 15 | CURATE THE FAMILY LIBRARY | A small correct library beats a large speculative one, every time. |
| 16 | ONE OWNER FOR THE PROJECT TEMPLATE | Not a committee. Version it. Review it between projects, never during. |
| 17 | TEST YOUR IFC EXPORT AT CONCEPT STAGE | Not at handover. What exports depends on mapping you have to set up. |
| 18 | SPECIFY INFORMATION, NOT DIMENSIONS | "Asset data per the AIR" beats "6D BIM" in every contract ever written. |
| 19 | CLOSE INACTIVE VIEWS | Revit regenerates every open view. Cheapest performance fix available. |
| 20 | RECORD THE DECISION, NOT JUST THE OUTCOME | Coordinate system, datum owner, version, workset structure. In the BEP, not in someone's memory. |

## 7. Model Health Tip (20)

| # | Headline | Body |
|---|---|---|
| 1 | TRACK THE TREND, NOT THE NUMBER | 400 stable warnings is a different situation from 400 that were 100 last week. |
| 2 | EXPORT WARNINGS WEEKLY | When something breaks, you will know which week it broke in. |
| 3 | FIX DUPLICATES FIRST | Duplicate instances silently double your quantities. Nothing warns you. |
| 4 | DUPLICATE MARK VALUES BREAK TAGGING | And scheduling. High priority, always. |
| 5 | UNENCLOSED ROOMS BREAK AREA SCHEDULES | And your compliance checks. Fix the walls or add separation lines. |
| 6 | PURGE MORE THAN ONCE | Purging makes further items unused. Run it until the list is empty. |
| 7 | REVIEW BEFORE YOU PURGE | Standard template types you have not used yet will be removed. |
| 8 | AUDIT ON OPEN, WEEKLY | And always before issuing to a CDE. |
| 9 | WATCH THE FILE SIZE TREND | A sudden jump means an import, a huge family, or a runaway link. |
| 10 | COUNT YOUR IN-PLACE FAMILIES | A rising count means modelling shortcuts are creeping in. |
| 11 | NESTED GROUPS ARE A PERFORMANCE KILLER | One of the most common causes of an unusably slow model. |
| 12 | CHECK FOR IMPORTED CAD | Manage Links → CAD Formats. Any import rather than link is worth investigating. |
| 13 | VIEWS NOT ON SHEETS | Working views are fine. Three hundred orphans are not. |
| 14 | NINE CHECKS, TWENTY MINUTES, EVERY FRIDAY | Warnings, size, purge, audit, imports, in-place, rooms, groups, orphan views. |
| 15 | RECORD THE NUMBERS | One line per week. After two months it tells you exactly when things went wrong. |
| 16 | MODELLING FAR FROM THE ORIGIN | Causes accuracy and display problems that look like random bugs. |
| 17 | A MODEL THAT ONLY YOU CAN USE | Is not a BIM model. Every question routing back to one person is a health problem. |
| 18 | HEALTH IS MAINTENANCE, NOT RESCUE | Twenty minutes a week prevents the two-day recovery. |
| 19 | PUT IT IN THE BEP WITH AN OWNER | Model health with no named owner does not happen. |
| 20 | IF IT IS BEHAVING STRANGELY, AUDIT IT | Random crashes and unselectable elements usually mean file corruption. |

## 8. Family Tip (20)

| # | Headline | Body |
|---|---|---|
| 1 | REFERENCE PLANES BEFORE GEOMETRY | Always. Nothing flexes if you build geometry first. |
| 2 | NAME YOUR REFERENCE PLANES | Unnamed planes cannot be selected as work planes later. |
| 3 | LOCK EVERY SKETCH LINE | The padlock is the whole technique. Unlocked geometry does not follow parameters. |
| 4 | FLEX BEFORE YOU LOAD | Change the parameter, press Apply, watch the geometry. Every time. |
| 5 | THE TEMPLATE DECIDES THE CATEGORY | And the category is hard to change later. Choose deliberately. |
| 6 | START FROM A SIMILAR FAMILY | Rather than a blank template, whenever you can. |
| 7 | TYPE OR INSTANCE? | If two elements of the same type could legitimately differ, it is an instance parameter. |
| 8 | TAG AND SCHEDULE MEANS SHARED | If a value must appear in both, it has to be a shared parameter. That is the whole answer. |
| 9 | ONE SHARED PARAMETER FILE | Central, backed up, one owner. Never regenerate it. |
| 10 | NEVER REGENERATE THE SHARED PARAMETER FILE | New GUIDs. Everything referencing the old file silently stops matching. |
| 11 | NESTED FAMILIES NEED SHARED PARAMETERS | Or the nested content cannot be scheduled. |
| 12 | KEEP FAMILIES AS SIMPLE AS THEIR PURPOSE | Level of information need applies to content, not just models. |
| 13 | IN-PLACE FAMILIES SHOULD BE RARE | Unreusable, file-bloating, and they schedule inconsistently. |
| 14 | MAKING THE SAME IN-PLACE TWICE? | It should be a loadable family. |
| 15 | FACE-HOSTED IS USUALLY THE FLEXIBLE CHOICE | Especially for MEP fixtures. |
| 16 | CURATE, DO NOT ACCUMULATE | A small correct library beats a large speculative one. |
| 17 | CONSISTENT PARAMETERS ACROSS A CATEGORY | So schedules work across families, not just within one. |
| 18 | NAME TYPES SO SOMEONE ELSE UNDERSTANDS | `SGL-FLUSH-900x2100`, not `Door 4`. |
| 19 | REVIEW BEFORE IT ENTERS THE LIBRARY | Once it is in, it will be used for years. |
| 20 | A FAMILY THAT WILL NOT FLEX | Has a missing lock. It is almost always a missing lock. |

## Scheduling the tip bank

**Wednesday slot, 52 weeks.** Rotate through formats so the same one never appears twice in
three weeks:

```
W1  Shortcut     W2  Common Mistake   W3  BIM Fact        W4  Tip of the Week
W5  Best Practice W6  Did You Know     W7  Productivity    W8  Model Health
W9  Family Tip    W10 Documentation    W11 Shortcut        W12 Common Mistake
... repeat
```

**Rules:**

- Match the tip to the week's Monday topic wherever possible. A shortcut tip in the week you
  taught walls should be `WA`.
- Never post a shortcut you have not verified in your own `KS` dialog.
- Every BIM Fact must carry its source on the card, not just in the caption.
- These also serve as WhatsApp status content — see `../whatsapp/status-series.md`.
