# Revit Tutorial Series — Curriculum Index

A beginner-to-competent Revit course, sequenced so each tutorial only assumes what came before.

**Every tutorial follows the same structure:**

```
Objective · Difficulty · Estimated time · Prerequisites
Step-by-step instructions
Tips
Common mistakes
Professional workflow
Shortcuts used
```

---

## Important note on keyboard shortcuts

Revit keyboard shortcuts **can be customised, and defaults vary between versions and
disciplines**. Every shortcut given in this series is listed as commonly-default, and should be
verified against your own installation.

**Check yours:** type `KS`, or go to **View tab → User Interface → Keyboard Shortcuts**. That
dialog is the authority for your install — not this document, and not any tutorial online.

`[Content note]` Building a post around "type KS to see every shortcut you actually have" is
more useful and more honest than publishing a shortcut list, and it never goes out of date.

## Index entries for tutorials not yet fully written

Each entry gives enough to teach the topic and to expand into a full tutorial later. They follow
the same structure in compressed form.

### 01 — Installing Revit and understanding versions
**Objective:** install correctly and understand the version trap. **●** · 30 min
**Key content:** subscription and licensing · which year version to install (match your
collaborators, not the newest) · the one-way upgrade rule.
**The critical point:** a model saved in a newer Revit cannot be opened in an older one. Ever.
Version must be agreed in the BEP before work starts, and matched across the whole project team.
**Common mistake:** installing the newest version because it is newest, then being unable to
open a consultant's model — or worse, upgrading theirs and locking them out.

### 08 — Reference planes and work planes
**Objective:** control where you are drawing in 3D space. **●●** · 30 min
**Key content:** creating reference planes (`RP`) · naming them so they can be selected as work
planes · setting the work plane before modelling in elevation · why families depend on this
entirely.
**Common mistake:** modelling in an elevation view without setting a work plane, and finding the
element is in the wrong place in plan.

### 17 — Curtain walls
**Objective:** build a curtain wall with a controlled grid. **●●** · 60 min
**Key content:** curtain wall as a wall type · grids, mullions, panels · curtain grid vs curtain
wall type · embedding curtain walls in host walls · swapping a panel for a door.
**Common mistake:** placing curtain grids manually on every wall instead of setting the vertical
and horizontal grid pattern in the type. The first is unmaintainable; the second updates
everywhere.

### 18 — Stairs and railings
**Objective:** produce a code-checkable stair. **●●●** · 90 min
**Key content:** stair by component vs by sketch · run, landing, support · riser and tread rules
in the type · railing types and host · multistorey stairs.
**Common mistake:** fighting the stair tool instead of fixing the levels. Most stair problems are
level height problems.

### 23 — Materials
**Objective:** set materials up so they serve graphics, schedules and takeoffs. **●●** · 45 min
**Key content:** identity, graphics, appearance, physical, thermal tabs · surface pattern vs cut
pattern · material takeoff dependence on correct assignment · duplicating rather than editing
library materials.
**Common mistake:** editing a shared library material and changing it everywhere in the project.

### 28 — Annotations and text
**Objective:** annotate without creating maintenance debt. **●** · 30 min
**Key content:** text types set in the template, not per view · leaders · model text vs
annotation text · why annotation is view-specific.
**Common mistake:** typing information that a tag could read from the model. The typed version
will not update.

### 29 — Dimensions
**Objective:** dimension so the drawing updates when the model changes. **●** · 45 min
**Key content:** aligned (`DI`), linear, angular, radial · dimension references — wall face,
centre, core · witness line editing · dimension types in the template.
**Common mistake:** dimensioning to an arbitrary reference so the dimension does not follow the
element when it moves.

### 30 — Tags
**Objective:** tag reliably and understand why a tag is blank. **●●** · 45 min
**Key content:** tag by category (`TG`) · tag all not tagged · loading the right tag family ·
the tag reads a parameter — blank tag means blank parameter · shared parameters for custom tags.
**Common mistake:** assuming the tag is broken. Check the element's parameter first, every time.

### 31 — Legends
**Objective:** build a legend that can be reused. **●●** · 30 min
**Key content:** legend views · legend components · the one view type that can be placed on
multiple sheets.
**Professional note:** legends belong in the project template, built once.

### 35 — Exports: DWG, IFC, NWC
**Objective:** export something the recipient can actually use. **●●** · 45 min
**Key content:** DWG export layer mapping · IFC export setup and property set mapping · NWC
export for Navisworks federation · testing the export by reopening it.
**The critical point:** for IFC, what exports depends on mapping. Geometry exports easily;
information exports only if you deliberately map parameters into property sets. Test at concept
stage, not at handover. (See `../knowledge-base/level-3-advanced.md` L3.09.)

### 41 — Copy/Monitor
**Objective:** monitor another discipline's datums for change. **●●●** · 45 min
**Key content:** Collaborate tab → Copy/Monitor → Select Link · copying levels and grids ·
coordination review when the source changes · which discipline should author datums.
**Common mistake:** two disciplines both authoring grids. Agree one author at project start.

### 46 — Phasing
**Objective:** handle existing, demolition and new correctly. **●●** · 60 min
**Key content:** phase created and phase demolished on every element · view phase and phase
filter · graphic overrides per phase status · demolishing with the Demolish tool rather than
deleting.
**Common mistake:** deleting existing elements instead of demolishing them. Deleted elements
cannot appear on a demolition plan.

### 47 — Design options
**Objective:** carry genuine alternatives without polluting the model. **●●** · 45 min
**Key content:** option sets and options · adding elements to an option · main model vs option ·
views set to display a specific option · accepting the primary.
**Common mistake:** using design options as a filing cabinet for abandoned ideas. Accept or
delete — they carry a permanent performance cost.

### 48 — Topography and site
**Objective:** model a site surface you can cut and schedule. **●●** · 60 min
**Key content:** toposurface by points or imported data · building pad · subregion vs split
surface · property lines · cut and fill schedules.
**Common mistake:** modelling the site far from the internal origin, which causes accuracy and
display problems throughout the project.

### 49 — Rendering
**Objective:** produce a presentable image without leaving Revit. **●●** · 60 min
**Key content:** camera views · sun and shadow settings · appearance assets · render quality vs
time · when to export to a dedicated visualisation tool instead.
**Professional note:** Revit is not a rendering engine of last resort. Presentation-grade
visualisation generally belongs in a specialist tool. Know where the line is.

## Suggested teaching order for content

The curriculum order above is the right order to *learn* in. It is not the right order to
*publish* in — publishing should follow `../strategy/one-year-content-strategy.md`, which
interleaves Revit tutorials with BIM concepts so the audience understands why a technique
matters before learning it.

**Rule:** never publish a technique before publishing the concept it serves. Teaching worksets
before teaching why coordination requires them produces people who can click the buttons and
cannot make the decisions.
